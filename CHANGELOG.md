## 2026-09-07 — wiki-os v10, layer-rules-template v8: one refresh command, meeting notes as an inflow, lint as the last step; sync.md renamed githubsync.md
- **§4 gains "propose the wiki update in the moment":** when a decision, milestone, changed position, or durable fact lands in conversation, name the line and its home and offer to write it; on yes, write it; the log records what was and was not written. ## 2026-08-05 — conventions v4
- `system/conventions.md` v3 → v4 — **new rule in §4: never defer the session log behind a pending confirmation.** Write it before the session goes idle with what is known, mark unsettled facts open, and amend if the answer arrives. Ported from the origin install v9 → v10 (Ben adopted 2026-08-05).
- **Origin:** a negotiation-drafting session ended with "tell me when it's sent and I'll write the session log and update the deal file." The owner sent the email and never returned to that conversation, so the log, two deal-file updates, and a correction the owner had made in-session all sat behind a confirmation that never came. The next refresh pass read "no log" as "no session," and a retroactive log had to be reconstructed from the session transcript two days later.
- **Why it generalizes:** any install where the model offers to do bookkeeping "once you confirm" has this failure mode, and it is silent — the loss is invisible until a sweep happens to look. It also compounds the v3 change: once session logs are the primary integration channel, a missing log is a missing integration.

## 2026-08-05 — conventions v3
- `system/conventions.md` v2 → v3 — **§8 gains the session-log sweep as step 2, named the primary integration channel.** Two install changes ported together:
  - **The sweep step itself** (origin install v6 → v7, 2026-07-28; missed by the v2 port, which carried only the meeting-bullets rule): read every `Claude Session` log across the layer newer than `.canvas/last_log_sweep`, pointer-never-source, big-things-only bar, one decisions file capped at seven ranked questions with recommended defaults, cap dropped for backlog catch-ups, marker updated only on completion.
  - **The primary-channel framing** (origin install v8 → v9, 2026-08-05). **Origin:** the owner stated plainly that he does not make entries into the `log.md` buffers — decisions are committed to the wikis during the working conversation, and the conversation's log is saved into the nearest `Logs/` folder for a closer read later. §8 step 2 now says that closer read *is* the sweep, that it must reach the `Logs/` folders inside project, spoke, and sub-folders rather than just the layer root, and that its main job is verification (confirm claimed writes reached their targets; catch the residue). §5 gains the matching reality note: the buffer pass stays, expected to be a fast no-op most weeks.
- **Why it generalizes:** any install whose owner works in conversation rather than by dictating notes will starve the §5 buffers the same way; a refresh that reads only the buffers reads empty files while the conclusions sit in session logs. The verification emphasis is what keeps a self-integrating workflow honest without re-ingesting the model's own output.

## 2026-07-29 — conventions v2
- `system/conventions.md` v1 → v2 — **new rule in §2: meeting and call entries are bullets, not narrative.** A wiki entry recording a meeting captures the moves, the decisions, and the crises as a bulleted list with bolded leads; narrative prose is not allowed. The full account goes in the session log (§4), and **where a log exists the entry names it by filename**, so the bullets can be trimmed hard without losing the record.
- Ported up from the origin install (its conventions file v7 → v8 and its private layer schema v7 → v8, which now links to the rule rather than restating it). **Origin:** the owner's own read of his deal files after a hard negotiation — the prose meeting write-ups had become "both too long and too hard to read as a human," and the moment a counterparty conceded something was buried mid-paragraph.

The naming requirement is what makes aggressive trimming safe rather than lossy.
